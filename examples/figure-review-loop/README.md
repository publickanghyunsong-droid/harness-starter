# 예제: 그림 검토 루프

이 폴더는 14장 한 장을 위한 자립적이고 재현 가능한 예제다. 초안 그림 세 장을
검토 화면에서 훑고, 피드백을 남기고, 그 피드백을 반영해 그림을 고치는 과정
전체를 담았다.

## 실제 사례 대신 합성 데이터를 쓴 이유

이 실습에 원래 쓰려던 것은 실제 분석이었다. 그런데 그 분석은 공개 전 검토
게이트를 통과하지 못했다(데이터와 그 안의 표현 방식 일부가 공개하기에 안전하지
않았다). 그래서 처음부터 안전하게 공개할 수 있는, 지어낸 숫자로 다시 지었다.
이 폴더 안 어떤 값도 실제 관측·예측·손실 추정치가 아니다. 여기 있는 모든 숫자는
`scripts/generate_data.py`에서 나온다. 정해진 시드로 고정된 난수 생성기다.
정확한 값과 재현하는 법은 `run_manifest.md`를 본다.

## 무엇이 들어 있나

```
dashboard.html         맨 처음 열 검토 화면(아직 검토를 거치지 않은 초안 그림을 띄운다)
data/                  합성 데이터 3종(생성한 것이지 내려받은 게 아니다)
scripts/               생성 + 렌더링 코드(아래 데이터와 초안 그림을 다시 만들어 낸다)
figures/               초안 PNG 세 장(각각 결함을 하나씩 일부러 심었다)
run_manifest.md        환경, 해시, 정확한 재현 명령, 대조할 수치
figures_manifest.md    검토 화면을 지을 때 쓴 대응표(어떤 파일이 무엇인지)
feedback/              새로 내보낸 피드백 .md 파일을 여기 떨어뜨린다(쓰기 전엔 비어 있다)
loop-history/          정답지. 반영을 마친 뒤 비교할 때 연다
```

## 세 그림

세 그림에는 각각 의도적으로 넣은 결함이 하나씩 있다. 그림이 조용히 독자를
잘못 이끄는 흔한 방식들이고, 셋 다 일부러 서로 다른 종류다. 세 장을 다
훑어야 세 가지 교훈을 배우지, 한 교훈을 세 번 되풀이 배우는 게 아니다.
무엇이 결함인지는 여기 적지 않는다. 그림을 보고 직접 찾는다.

1. **`fig1_bar`**는 여섯 지역의 지어낸 "손실지수"를 비교하는
   막대그래프다.
2. **`fig2_grid`**는 지어낸 "위험 요인 격자"(가운데 뜨거운 지점이
   있는 숫자 격자라고 생각하면 된다)를 색으로 보여주는 히트맵이다.
3. **`fig3_scenarios`**는 "시나리오" A와 B 두 히트맵을 나란히 놓은
   그림이다.

이 세 그림을 따라가는 데 기후나 재해 리스크 배경지식은 필요 없다. 매번
핵심은 일반적인 그리기 습관이지, 이 분야에 한정된 사실이 아니다. "위험
요인"·"손실지수" 같은 틀은 이 책의 다른 예제가 그 분야에서 왔기 때문에
남겨 뒀을 뿐이다. 밑에 깔린 데이터는 합성이니 이 틀은 실제 참조가 아니라
장식으로 읽으면 된다.

## 직접 재현하기

```bash
cd scripts
python3 generate_data.py
python3 fig1_bar.py
python3 fig2_grid.py
python3 fig3_scenarios.py
```

`numpy`, `pandas`, `matplotlib`만 있으면 된다(비교적 최신 버전이면 어느
것이든 된다. 이 예제를 짓고 검사한 정확한 버전은 `run_manifest.md`에 있다).
지리공간 라이브러리도, 큰 다운로드도, API 키도 필요 없다.

## 이 예제에서 누가 무엇을 만들었나

- 데이터, 스크립트, 초안 그림은 이 폴더 안에서 만들고 문체 검사도
  여기서 마쳤다.
- 검토 가능한 화면 자체(실제로 클릭해 들어가 그림에 피드백을 남기는 그 화면)는
  이 예제의 다른 조각이다. 워크플로의 다른 부분이 지은 것이다.

## 초안 검토하기: 검토 화면 열기

위 모든 것을 한데 묶어 실제로 클릭해 들어갈 수 있게 만든 파일이 같은 폴더
안의 **`dashboard.html`**이다. 설치도, 서버도, 인터넷 연결도 필요 없다.
자립적인 HTML 파일 하나다.

- 이 폴더를 내려받거나 클론한다.
- `dashboard.html`을 아무 브라우저에서나 연다(더블클릭하거나, 주소창에 파일
  경로를 붙여 넣는다).
- 그림당 카드 한 장씩, 카드 세 장이 보인다. 각 카드에는 그 그림이 무엇을
  보여주는지 짧게 풀어 쓴 해설과 오른쪽에 피드백 패널이 붙어 있다.
- 위쪽 "Theme: auto" 버튼은 그 자리에서 명암 테마를 바꾼다.

자바스크립트가 꺼져 있어도 그림과 해설은 그대로 뜬다(순수 HTML이다). 피드백
입력창과 명암 전환만 작동을 멈춘다.

지금 `dashboard.html`에 떠 있는 것은 세 그림 모두 **아직 검토를 거치지 않은
초안(v1)**이다. 일부러 그렇게 뒀다. 해설 텍스트는 각 그림이 무엇을 보여주는지만
말하지, 무엇이 잘못됐는지는 짚지 않는다. 요지는 답을 듣기 전에 실제 검토자가
하듯 그림 자체를 먼저 눈으로 보는 것이다. 이 문서를 더 읽기 전에 무엇을
고치라고 말할지 직접 찾아보길 권한다.

## 정답지

정답지는 `loop-history/`에 있다. 반영을 마친 뒤 비교할 때 연다.

## 자기 피드백 남기기(세 번째 판 시작하기)

- `dashboard.html`에서 아무 카드나 골라 "피드백" 버튼을 누른다.
- 오른쪽 입력창에 무엇을 고치고 싶은지 적는다(Cmd/Ctrl+Enter로도 추가된다).
  원하는 만큼 여러 카드에 반복한다.
- "반영 요청 (md 내보내기)" 버튼을 누른다. `.md` 파일이 하나 내려받아지고,
  목록은 그대로 남는다. 지우려면 항목마다 직접 지운다.
- 그 파일을 이 폴더의 `feedback/`에 떨어뜨린다(이미 한 판이 돈 기록을 담은
  `loop-history/feedback/`와는 다른, 지금은 비어 있는 폴더다). 그게 다음
  판을 만들 누군가 또는 무언가의 입력이 된다.

입력한 피드백은 브라우저의 `localStorage`에만 남는다. 같은 브라우저에서
페이지를 새로고침해도 남아 있지만, 다른 기기나 다른 브라우저에서는 안
보인다. 실제로 지켜 두는 방법은 파일로 내보내는 것뿐이다.

## 이 검토 화면의 형식, 재사용하고 싶다면

`dashboard.html`이 따르는 규칙은 짧아서 그대로 복사해 자기 프로젝트에
붙이고 자기 그림으로 채우면 된다.

- **그림당 카드 한 장.** 카드마다 해설은 항상 같은 네 부분이다. 이 그림이
  무엇을 주장하는가, 그 근거(수치·사실 1–3개), 결론(정확히 한 문장으로,
  독자가 지금부터 무엇을 하거나 믿어야 하는가), 관련이 있다면 한계(이 그림이
  증명하지 *못하는* 것)까지.
- **카드당 상태 배지는 하나만.** 이 예제에서는 "new"(첫 판)와 "updated"
  (피드백을 반영해 고친 판) 둘뿐이다.
- **피드백은 요약하지 않고 원문 그대로 내보낸다.** 검토자 자신의 말이
  기록의 원본이지, AI가 바꿔 쓴 말이 원본이 아니다.
- **내보내도 화면 목록은 그대로 둔다.** 내보낸 파일이 기록의 원본이다.
- **HTML 파일 하나, 외부 의존성 0.**(CDN도, 웹폰트도 없다.) 그래야 몇 년
  뒤에도, 오프라인에서도, 별다른 준비 없이 열린다.

## 파일 하나로 끝나야 하는 이유

검토 화면은 그림을 base64 데이터 URI로 HTML 안에 직접 담는다. 그래야
그 파일 하나만 다른 곳으로 옮겨도, 네트워크가 없어도, 옆에 `figures/`
폴더가 없어도 화면이 그대로 열린다. 이 규칙의 요지는 그것이다. 검토 화면은
인터넷이 끊긴 자리에서도, 몇 년 뒤에도 열려야 한다.

처음부터 이랬던 건 아니다. 첫 판은 `figures/*.png`를 상대경로로 끌어왔다.
그래서 HTML 파일 하나만 옮기면 빈 상자만 뜨는데, 원고 본문은 이 화면이
자립적이라고 주장하고 있었다. 2026-08-23에 고쳤다.

그림을 새로 만든 뒤 다시 담거나, 외부 경로가 하나도 안 남았는지 확인하려면:

```bash
python3 scripts/inline_figures.py dashboard.html
python3 scripts/inline_figures.py --check dashboard.html    # 외부 참조가 남았거나 옛 그림이 남아 있으면 exit 1
```

화면 속 그림마다 `data-src="figures/…png"` 속성에 원본 파일 경로가 적혀 있고,
스크립트는 돌릴 때마다 그 파일에서 그림을 다시 담는다. 그래서 그림 파일을
같은 이름으로 다시 그렸으면 위 명령 한 줄이면 화면이 바뀐다(그림이 그대로면
결과도 그대로다). 고친 그림을 새 이름(예: `figures/fig1_v2_mine.png`)으로
저장했다면 `dashboard.html`에서 그 카드의 `data-src` 두 곳(`<a>`와 `<img>`)을
새 경로로 바꾼 뒤 같은 명령으로 다시 담는다.

`--check` 모드는 게이트에 걸어 둘 만하다. 다만 이 검사기의 첫 판은 항상
성공만 찍었다는 점을 짚어 둔다. 참조를 먼저 다 치환한 다음 그 결과를 셌기
때문에, 고치기 전에도 고친 뒤에도 똑같이 통과했다. 언제나 통과하는 게이트는
게이트가 없는 것보다 나쁘다. 지금은 원래 텍스트를 센다.

## 한계

- 이 예제 안 모든 숫자는 합성이다. "F 지역의 손실지수가 더 높다"거나
  "시나리오 B가 10퍼센트 더 높게 튄다"를 실제 세계에 대한 주장으로 읽지
  않는다. 이 예제가 보여주는 건 검토 도구와 그것을 쓰는 법, 그것뿐이다.
- 그림 안 텍스트(제목·축·범례)는 이식성을 위해 일부러 영어로 뒀다
  (`scripts/common_style.py` 참고). 검토 화면 자체의 UI 텍스트는 한국어다.
  이 나뉨은 실수가 아니라 의도한 것이다.
- 이 예제에 남은 기록은 피드백 한 판뿐이다. 실무에서는 같은 종류의 실수가
  보통 두세 번은 반복돼야 상시 규칙으로 세울 만하다는 판단이 선다. 한 판의
  결과만으로 지나치게 일반화하지 않는다.
