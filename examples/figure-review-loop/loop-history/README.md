# 정답지 — 반영을 마친 뒤 비교할 때 연다

이 폴더는 정답지다. 초안 세 장을 직접 검토하고, 피드백을 내보내고, 그
피드백으로 그림을 고치는 데까지 마친 뒤에 연다. 먼저 열면 "무엇이 문제인지
스스로 찾아보기"가 스포일러가 된다.

세션에게 그림을 고치게 할 때도 이 폴더는 근거로 쓰지 않는다. 근거는 `feedback/`에
떨어뜨린 피드백 파일뿐이다.

## 이 폴더에 든 것

```
dashboard-v2-reviewed.html   고친 그림 + "무엇이 바뀌었나" 요약(그림은 파일 안에 내장)
feedback/                    초안을 보고 실제로 남겼던 피드백 .md
figures/                     수정본(v2) PNG 세 장
scripts/                     수정본(v2)을 그리는 코드(초안 코드는 ../scripts/)
```

## 이미 한 번 돈 루프(v1 → 피드백 → v2)

이건 연출된 화면 캡처가 아니다. 바로 이 초안들을 대상으로 이 검토 루프
한 판이 실제로 이미 돌았고, 세 단계 전부 디스크에 그대로 남아 있다.

1. **`../dashboard.html`**에는 결함 하나씩 아직 남아 있는 초안 **v1** 그림들이
   담겨 있다.
2. **`feedback/figure-review-loop-v1-feedback-20260803-142400.md`**에는
   1단계를 보고 남긴 피드백이 담겨 있다. 검토 화면이 실제로 내보내는 형식 그대로
   (그림별로 묶고, 평서문으로, 시각을 찍어) 담겨 있다.
3. **`dashboard-v2-reviewed.html`**은 그 피드백을 반영한 뒤의 **v2** 결과다.
   맨 위에 각 수정을 그것을 불러온 지적으로 되짚는 "무엇이 바뀌었나" 절이
   붙어 있다.

이 셋을 순서대로 읽으면 "여기가 이상하다"에서 "이렇게 바뀌었다"로 이어지는
줄이 하나로 맞아떨어지는 게 보인다. 예를 들어 피드백 파일의 Fig 1 지적
("축이 85에서 시작하는데, 실제 차이가 저렇게 큰가")은 `dashboard-v2-reviewed.html`의
Fig 1 변경 기록("y축을 0에서 시작하도록 재설정")에 그대로 대응한다.

## 세 그림의 결함과 고치는 법

각 결함은 일부러 서로 다른 범주(축·범위/누락된 라벨·단위/비교 불가능한
색상 범위)로 골랐다. 세 번의 루프 반복이 같은 교훈을 되풀이하지 않도록
하려는 것이다.

| 초안 | 수정본 | 한 줄 요약 결함 |
|---|---|---|
| `../figures/fig1_bar_v1.png` | `figures/fig1_bar_v2.png` | y축이 깔끔한 0 기준 범위 대신 [85,98]로 잘려서, 지역 간 실제 차이 8.5%가 시각적으로 3–4배 차이로 읽힌다 |
| `../figures/fig2_grid_v1.png` | `figures/fig2_grid_v2.png` | 컬러바에 숫자는 있지만 단위·라벨이 없어서, 색이 어떤 값·단위를 나타내는지 독자가 알 수 없다 |
| `../figures/fig3_scenarios_v1.png` | `figures/fig3_scenarios_v2.png` | 시나리오 A·B 패널이 각자 자기 색상 범위로 독립 조정돼, 실제로는 최댓값 차이가 약 10%뿐인데도 시각적으로는 구분이 안 된다(둘 다 똑같이 "뜨겁게" 보인다). 차이 패널도 따로 주어지지 않는다 |

1. **`fig1_bar`**는 여섯 지역의 지어낸 "손실지수"를 비교하는
   막대그래프다. 초안은 세로축을 0에서 시작하지 않고 가장 작은 막대 값
   바로 아래에서 시작한다. 이 선택 하나로 지역 간 실제 차이 약 8퍼센트가
   3에서 4배는 벌어져 보이는 막대 높이로 바뀐다. 고치는 방법은 단순히 축을
   0에서(또는 다른 깨끗하고 정직한 기준선에서) 시작하는 것뿐이다. 합성
   데이터도 이 왜곡이 드러나도록 값을 좁은 띠(0–100 지수 중 88–97)에 모아
   지었다.

2. **`fig2_grid`**는 지어낸 "위험 요인 격자"(가운데 뜨거운 지점이
   있는 숫자 격자라고 생각하면 된다)를 색으로 보여주는 히트맵이다. 초안의
   컬러바에는 숫자가 있지만, 그 숫자가 무엇을 뜻하는지, 단위가 무엇인지 말해
   주는 라벨이 없다. 초속인가, 비율인가, 임의로 정한 지수인가. 독자는 알
   방법이 없다. 고치는 방법은 빠진 라벨과 단위를 채워 넣는 것이다. 수정본은
   컬러바에 "Wind speed (m/s)", 축에 km 단위를 달았다.

3. **`fig3_scenarios`**는 "시나리오" A와 B 두 히트맵을 나란히 놓고,
   수정본에서는 세 번째 패널로 둘의 차이까지 보여준다. 초안은 각 패널의
   색을 그 패널 자신의 값 범위에 맞춰 독립적으로 배정한다. 그러면 실제로는
   진짜 세기 차이가 약 10퍼센트밖에 안 나는 두 뜨거운 지점이 그림에서는
   똑같이 심각해 보인다. 그림만 봐서는 진짜 격차의 크기를 알 수 없다.
   고치는 방법은 두 패널에 같은 색상 범위를 공유시키고, 명시적인 차이 패널
   (B − A, 0을 가운데 둔 발산형 색)을 더하는 것이다. 그러면 진짜 격차가
   눈에 보이게 된다.

각 수정이 코드에서 정확히 무엇인지는 `scripts/fig*.py` 머리 주석에 그대로 있다.

## 검토 화면 캡션용 메모(쉬운 말로, 배경지식을 전제하지 않는다)

- 그림 1은 막대그래프다. 결함은 축을 이용한 눈속임이다. y축 아래를 잘라
  작은 차이를 크게 보이게 만든다.
- 그림 2는 히트맵이다. 결함은 누락이다. 색상 범위는 있는데 그 색이 무엇을
  뜻하는지, 단위가 무엇인지 알려 주는 라벨이 없다.
- 그림 3은 두 패널 비교다(수정본에는 세 번째 "차이" 패널이 더해진다).
  결함은 각 패널의 색이 독립적으로 배정된 것이다. 그래서 두 패널이
  똑같이 강렬해 보여도 실제로는 크게 다를 수도, 조금 다를 수도 있는데
  그림만 봐서는 알 수가 없다.

## 수정본 다시 그리기

```bash
cd loop-history/scripts
python3 fig1_bar.py
python3 fig2_grid.py
python3 fig3_scenarios.py
```

데이터(`../../data/`)와 공통 스타일(`../../scripts/common_style.py`)은 초안과
같은 것을 쓴다. 결과는 `loop-history/figures/`에 떨어진다. 각 스크립트는
대조값도 찍는다.

- fig1: 지역 간 실제 스프레드 = `8.5%`(최소 88.6, 최대 96.1)
- fig2: 격자 최소/최대 = `8.4 / 56.8`
- fig3: 실제 최댓값 격차 = `10.1%`(A 최대 43.0, B 최대 47.4)

그림을 새로 그렸으면 정답 화면에 다시 담는다.

```bash
python3 scripts/inline_figures.py loop-history/dashboard-v2-reviewed.html
python3 scripts/inline_figures.py --check loop-history/dashboard-v2-reviewed.html
```

(예제 폴더 루트에서 실행한다. `dashboard-v2-reviewed.html`은 그림을 이미
base64로 내장하고 있어서, 다시 담지 않아도 그대로 열린다.)

## 이 수정본이 "유일한 정답"은 아니다

`figures/*_v2.png`는 이 회차가 직접 낸 결함별 참조 수정본이다.
수정이 구체적으로 무엇인지 보여 주고 대조할 수 있도록 존재하지, 단순히
암시만 하려는 게 아니다. v1 초안을 대상으로 실제 검토 루프 세션을 돌리면
세부(예: 축 눈금을 어디서 깔끔하게 끊을지)가 다른 수정으로 수렴할 수
있다. 그건 예상된 일이지 모순이 아니다. 여기 있는 v2는 "정답 중 하나"이지
"유일한 정답"이 아니다.

이 예제는 피드백 한 판(v1 → v2)만 돌았다. 실무에서는 같은 종류의 실수가
보통 두세 번은 반복돼야 "컬러바에는 항상 라벨을 단다" 같은 상시 규칙으로
세울 만하다는 판단이 선다. 한 판의 결과만으로 지나치게 일반화하지 않는다.
