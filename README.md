# 하네스 스타터

『데이터를 다루는 사람들을 위한 하네스 엔지니어링』 3부(14·15장)의 실습 저장소다. 규약이 문서에만 적혀 있고 실제로는 안 지켜지는 간극을 잡는 최소 장치 모음이고, 필요한 것은 파이썬 3와 bash뿐이다.

받은 폴더에서 바로 작업한다. 다른 곳으로 복사하는 단계는 없다.

## 무엇이 들어 있나

| 파일·폴더 | 역할 |
|---|---|
| `AGENTS.md` | 이 저장소에서 일하는 규칙의 정본. `CLAUDE.md`는 이 파일을 가리키는 포인터다 |
| `docs/conventions.md` | 이 프로젝트의 규약. 만드는 자리든 감사하는 자리든 착수 전에 읽는다 |
| `docs/log.md` | 작업 로그. 점검 루틴이 돈 기록을 여기에 남긴다 |
| `harness.toml` | 점검 설정. 구획마다 보는 대상이 다르고, 구획을 지우면 그 점검은 「해당 없음」이 된다 |
| `harness/` | 기계 점검(`python3 -m harness.audit`)과 카나리 채점 코드 |
| `hooks/` | 되돌릴 수 없는 행동을 막는 훅. 기본으로 막는 것은 `git push` 하나다 |
| `.claude/settings.json` | 훅을 실제로 거는 배선(Claude Code 형식) |
| `.claude/agents/` | 에이전트 정의. 만드는 `analyst`와 감사만 하는 `auditor` |
| `.claude/skills/` | 되풀이하는 절차를 굳힌 파일. `new-convention`은 규약을 늘리는 절차다 |
| `preflight/` | 무거운 작업을 시작하기 전 부하를 보는 게이트 |
| `tests/` | 위 장치가 지금도 도는지 보는 시험 |
| `canaries.json` | 카나리 질문 목록(심화) |
| `templates/review.html` | 내 산출물에 붙이는 검토 화면의 빈 틀 |
| `examples/figure-review-loop/` | 결함이 심긴 그림 세 장과 검토 화면, 이미 한 판 돈 기록 |
| `prompts/` | 책의 프롬프트를 장·절별 텍스트로 모아 둔 곳 |

## 처음 할 일

1. **훅이 걸렸는지 잰다.** 파일이 있다는 것과 걸려 있다는 것은 다르다.

   ```bash
   bash tests/test_hook_wiring.sh
   ```

2. **점검을 돌린다.**

   ```bash
   python3 -m harness.audit
   ```

   처음에는 대부분 「해당 없음」이 뜬다. 정상이다. 점검이 볼 대상(작업 로그, 예약 작업, 커밋 이력)이 아직 없다는 뜻이지 고장이 아니다.

## 꺼진 구획은 필요할 때 켠다

`harness.toml`에서 지금 켜져 있는 것은 `[gate_debt]`, `[[smoke]]`, `[links]`, `[corpus]`, `[preflight]`, `[canaries]`다. 꺼져 있는 것은 아래 셋이고, 해당 줄의 `#`을 지우면 켜진다.

- `[routine]`의 `log_file`: 점검 루틴이 `docs/log.md`에 기록을 남기고 있는지 본다.
- `[scheduled]`: 배경에서 도는 예약 작업을 본다. 운영체제마다 명령이 다르다.
- `[git]`: 지난 회차 이후 개정된 규약을 커밋 이력에서 모은다. 커밋하지 않는 실습에서는 경고만 계속 나므로 꺼 둔다.

켠 뒤에는 점검을 다시 돌려, 그 항목이 판정에 새로 걸리는지 본다.

## 규약을 늘릴 때

`.claude/skills/new-convention/`의 절차를 따른다. 걸린 자리를 규약 한 줄로 적고, 검사기를 같이 넣어 한 번 돌려 보고, 검사기를 못 붙이겠으면 `⚠️checker 없음`이라고 적는다.

## 심화: 카나리 채점 (선택)

카나리는 규약이 문서에 있는데도 실제 작업을 시작할 때 안 걸리는 경우를 잡는다. `canaries.json`에 상황을 던지는 질문이 들어 있고, 그 질문을 **서브에이전트**(규약을 새로 읽는 신선한 컨텍스트)에 던진 뒤 `python3 -m harness.score_canaries <응답을 저장한 폴더>`로 채점한다. 이미 규약을 읽은 세션 자신에게 물으면 시험이 아니라 복창이 되므로, 반드시 다른 세션에 물어야 한다. `canaries.json`의 `expect` 정규식은 자기 프로젝트 규약에 실제로 쓰는 낱말로 바꿔야 시험이 날카로워진다.

## 되돌리기 전에 읽을 것

`harness.toml`과 `hooks/`의 주석에는 판정 기준을 왜 그렇게 정했는지가 적혀 있다. 기준을 바꾸기 전에 그 주석부터 읽는다. 검사기를 「항상 통과」로 고치는 것이 가장 흔한 실패이고, 고치기 전보다 나쁘다.
